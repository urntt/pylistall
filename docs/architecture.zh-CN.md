## 模块与数据流

| 模块 | 职责 | 结果或副作用 |
| --- | --- | --- |
| `cli.py` | 解析参数、验证根路径、规范化选项并组装输出 | 包含文本、文件数及警告的 `OutputResult` |
| `tree.py` | 遍历并渲染真实目录树 | 独立于内容过滤的目录树文本 |
| `selection.py` | 规范化模式、选择文件、识别二进制内容、读取及渲染内容 | 内容文本及选定文件数 |
| `gitlog.py` | 查找 `.git` 条目并调用 Git 日志 | 日志分组及警告 |
| `util.py` | 选择剪贴板后端并传送文本 | 写入系统剪贴板 |

```text
参数 -> cli：验证根路径并构造选项
             |-> tree：遍历 -> 排序 -> 渲染
             |-> gitlog（可选）：查找 .git -> git log -> 分组
             |-> selection：枚举 -> 过滤 -> 读取 -> 渲染
         cli：组装根路径 + 目录树 + 日志 + 内容
             -> 可选 stdout 预览 -> 剪贴板 -> 成功提示
```

各模块独立遍历。排除文件内容后，路径仍可出现在目录树中，也不影响 Git 查找。
当前没有共用的遍历索引或流式输出管线。

## 目录树

不递归时，`tree.py` 列出直接子项，包括未展开的文件夹；递归时构造嵌套的
`TreeEntry` 并用树形连接符渲染。文件夹排在文件之前，名称按大小写不敏感的方式排序，
文件夹以 `/` 结尾。只有 `-r` 控制展开，包含、排除和二进制选项均不影响目录树。

当前目录枚举错误按空列表处理。文件夹判断会跟随链接，递归建树没有循环保护。

## 内容筛选与读取

`selection.py` 在浅层收集时使用 `iterdir()`，递归发现文件时使用 `rglob("*")`。
模式通过 `fnmatch` 匹配文件名及使用 `/` 分隔的相对路径。
重复或逗号分隔的值统一去除首尾空白和空项；大小写规范化遵循平台上的 `fnmatch`，
匹配规则不是 Git ignore 语法。

筛选顺序如下：

1. 存在包含列表时，仅保留匹配的文件。
2. 排除匹配的文件，即使包含或二进制选项会选择该文件。
3. 判断二进制内容。显式包含规则的匹配可强制包含；否则必须由二进制策略允许。
   文本文件不需要 `-b`。
4. 按显示名称进行大小写不敏感的排序，再读取并渲染各文件。

裸 `-o` 才启用默认排除集。以 `**/` 开头的默认规则会派生根层级规则；
自定义模式保留普通 `fnmatch` 行为。例如，自定义 `**/.venv/**` 不匹配根层级的
`.venv/config.txt`。`.git/**` 针对根层级 Git 目录，不会排除所有嵌套仓库。
程序不加载 `.gitignore`。

二进制识别先检查已知扩展名，再读取有限的字节样本和一个前瞻字节。
NUL 字节表示二进制内容；严格的增量 UTF-8 解码允许采样边界切开的字符，
但会检查文件末尾的不完整字符。解码失败后，通过非文本字节比例启发式判断。
这不是整个文件的有效性验证；样本无法读取时按二进制处理。

内容以 UTF-8 解码，无法解码的字节替换显示。因此包含二进制文件只是生成解码文本，
不会解压文件或理解图片、文档。单文件上限会多读一个字节判断截断，
并添加 `[...TRUNCATED...]`。读取错误变成 `[Failed to read file: ...]` 内容块；
文件数表示选定的文件数，也包含读取失败的文件。

## Git 日志

没有 `-r` 时只检查根层级 `.git`；递归时查找 `.git` 目录和文件，
包括 worktree 使用的指针文件。每个条目的父目录作为仓库根目录，
调用 `git -C ... log --oneline --decorate`，可加数量限制。
日志组按绝对路径进行大小写不敏感的排序，并以 `.git` 绝对路径开头。

没有条目时，输出组装阶段添加 `[No .git found]`；空日志和子进程失败也使用文本标记。
请求日志时需要 PATH 上有 Git，无需 Git Python 库。
当前递归查找遇到错误时会丢弃已发现的条目，不提供详细的遍历失败信息。

## 输出与剪贴板

`cli.py` 先输出绝对根路径，路径位于十反引号的目录树围栏之外。
目录树为空时使用 `(empty)`。随后输出可选的 Git 分组，再输出以相对路径为标题、
十反引号为围栏的内容块。最终文本以一个换行结尾。
[README 示例](../README.zh-CN.md#输出格式)展示该格式。
如果文件包含相同分隔符，当前固定围栏不会进行转义。

`-p` 在复制之前打印组装文本，不是纯 stdout 模式。
macOS 使用 UTF-8 `pbcopy`，Windows 使用 UTF-16LE `clip`，其他平台先使用
UTF-8 `xclip -selection clipboard`，再尝试 pyperclip。
剪贴板失败会向上传播，CLI 尚无专门的无桌面回退或统一的友好错误处理。
目标路径无效时，打印错误并返回状态码 2，不尝试复制。

## 安全边界与当前限制

程序读取本地文件，以参数列表运行 Git 和剪贴板程序，并在内存中组装文本。
它不会上传数据或执行收集的文件内容。复制会替换用户剪贴板内容，粘贴目的地由用户决定。

- 没有自动秘密检测或敏感文件排除。隐藏的文本文件可能被收集；默认排除需裸 `-o`
  才启用，也不构成敏感数据边界。排除内容仍会在目录树中留下文件名。
- 没有统一的符号链接约束策略。文件链接可能读取根目录之外的内容；
  目录树中的文件夹链接可能越界或循环。内容发现行为也可能随 Python 版本不同，
  不应宣称收集范围被限制在根目录内。
- 没有输出总量预算。默认不限制文件大小，现有上限仅针对单文件，目录树和日志无上限。
  负数字节上限尚未显式拒绝，大型输入可能占用大量内存。
- 正常使用需要桌面剪贴板后端，`-p` 也一样。帮助和模拟测试无需桌面会话。

这些缺口仍是待完成的产品工作。修复其中一项时，应明确行为、更新双语文档和回归覆盖，
并考虑独立生成的目录树、日志和内容。
